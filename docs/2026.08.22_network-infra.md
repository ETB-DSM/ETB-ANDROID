# Phase 2 — 네트워크 인프라 구성

## 개요

Retrofit + OkHttp 기반 네트워크 레이어를 구성한다.  
인증 토큰 관리(`TokenStorage`), 요청 헤더 자동 주입(`AuthInterceptor`),  
401 시 토큰 자동 갱신(`TokenAuthenticator`), Hilt DI 모듈(`NetworkModule`)을 포함한다.

## 파일별 설계

### Qualifier Annotations

세 가지 OkHttp 클라이언트/Retrofit 인스턴스를 Hilt에서 구분하기 위한 qualifier.

```kotlin
// AppClient: App 서버 API용 (AuthInterceptor + TokenAuthenticator 포함)
@Qualifier @Retention(AnnotationRetention.BINARY) annotation class AppClient

// TmapClient: T-Map API용 (appKey 헤더 인터셉터 포함, Auth 없음)
@Qualifier @Retention(AnnotationRetention.BINARY) annotation class TmapClient

// RefreshClient: 토큰 갱신 전용 plain OkHttp (순환 의존성 방지)
@Qualifier @Retention(AnnotationRetention.BINARY) annotation class RefreshClient
```

### TokenStorage

```kotlin
@Singleton
class TokenStorage @Inject constructor(@ApplicationContext context: Context) {
    // EncryptedSharedPreferences with AES256_GCM MasterKey
    
    저장 항목: accessToken, refreshToken, userId, deviceId
    
    fun clearAll()  // 로그아웃 / 갱신 실패 시 전체 삭제
}
```

- 스레드 안전: EncryptedSharedPreferences 자체가 thread-safe
- TRD에 명시된 4개 항목만 저장

### AuthInterceptor

```kotlin
class AuthInterceptor @Inject constructor(private val tokenStorage: TokenStorage) : Interceptor {
    // 모든 App API 요청에 Authorization: Bearer {accessToken} 헤더 추가
    // accessToken이 null이면 헤더 없이 통과 (로그인 전 상태)
}
```

### TokenAuthenticator

```kotlin
class TokenAuthenticator @Inject constructor(
    private val tokenStorage: TokenStorage,
    @RefreshClient private val refreshClient: OkHttpClient,
    private val json: Json,
) : Authenticator {
    // 401 수신 시 동작:
    //   1. refreshToken 없으면 null 반환 (포기)
    //   2. synchronized로 중복 갱신 방지
    //   3. POST BASE_URL/api/v1/auth/refresh 직접 호출 (OkHttp, Retrofit 미사용 — 순환 의존성 방지)
    //   4. 성공 → accessToken/refreshToken 갱신 후 원래 요청 재시도
    //   5. 실패 → tokenStorage.clearAll() 후 null 반환 (로그인 화면 이동은 Phase 3 ViewModel이 담당)
}
```

**순환 의존성 해결:**  
NetworkModule에서 `@RefreshClient OkHttpClient`(인증 없는 plain 클라이언트)를 별도 생성해  
`TokenAuthenticator`에 주입한다. refresh 호출은 Retrofit을 사용하지 않고 OkHttp 직접 호출한다.

### NetworkModule

제공 목록:
| Binding | 타입 | 설명 |
|---------|------|------|
| `Json` | Json | ignoreUnknownKeys=true, isLenient=true |
| `TokenStorage` | TokenStorage | EncryptedSharedPreferences 래퍼 |
| `@RefreshClient OkHttpClient` | OkHttpClient | 인증 없음, refresh 전용 |
| `AuthInterceptor` | AuthInterceptor | |
| `TokenAuthenticator` | TokenAuthenticator | |
| `@AppClient OkHttpClient` | OkHttpClient | AuthInterceptor + TokenAuthenticator |
| `@TmapClient OkHttpClient` | OkHttpClient | appKey 헤더 자동 주입 |
| `@AppClient Retrofit` | Retrofit | BASE_URL, kotlinx.serialization |
| `@TmapClient Retrofit` | Retrofit | apis.openapi.sk.com, kotlinx.serialization |

## 에러 처리

| 상황 | 처리 |
|------|------|
| accessToken 없음 | AuthInterceptor가 헤더 없이 통과 |
| 401 수신 | TokenAuthenticator가 refresh 시도 |
| refresh 실패 | tokenStorage.clearAll() 후 null 반환 |
| 로그인 화면 이동 | Phase 3 AuthViewModel이 accessToken 상태 감지 후 처리 |
