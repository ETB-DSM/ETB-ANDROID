# PR #20 되돌리기 — 길안내/디바이스 상태 API 오적용 수정

## 배경

`docs/2026.08.30_navigation-device-embedded-api-realignment.md`(PR #20, `develop`에 이미 병합됨)는 Notion `ETB > Embedded와 통신 API` 스펙을 근거로 길안내 세션 생성/명령 저장/상태 변경과 디바이스 상태 조회를 App API v1(JWT)에서 Embedded API(userId/deviceId 기반, v1 없음)로 옮기는 작업이었다. 이때 사용자가 "Notion의 '설계중' 라벨은 오표시이고 실제로는 서버에 이미 구현되어 있다"고 확인해주어 이를 근거로 진행했다.

그런데 실제 배포된 백엔드(`localhost:8082`, `etb-be-api-1` 컨테이너)에 직접 요청을 보내 확인한 결과, **Notion 스펙은 아직 배포되지 않은 설계안**이었고 실제 서버는 원래 `api.md`(App API v1 JWT + Embedded 단수형 device/status)를 그대로 쓰고 있었다. PR #20이 앱을 존재하지 않는 엔드포인트로 바꿔버려 `develop`에서 길안내 세션 생성·명령 전송·디바이스 상태 조회가 전부 깨진 상태였다.

## 재발 방지

Notion 문서의 `진행상태` 라벨(설계중/개발중/완료)과 실제 배포 상태가 다를 수 있으므로, 앞으로 API 경로를 변경할 때는 Notion/api.md 등 문서만으로 판단하지 않고 **실제 떠 있는 서버에 직접 요청을 보내 라우트 존재 여부(404 vs 401/400)를 확인**한 뒤 반영한다.
