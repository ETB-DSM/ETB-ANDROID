# 재탐색 요청 폭주 억제 — 쿨다운/이동 게이트 + 업로더 dedup 복원

작성일: 2026.08.27

## 배경 / 문제

경로 이탈 판정이 계속 `REROUTE`를 낼 때(예: 정지 상태), 위치 업데이트(약 2초 간격)마다
TMAP 재탐색과 `/instructions` 전송이 반복돼 요청이 폭주한다. 원인은 두 가지.

1. **TMAP 폭주** — `handleReroute`의 `isRerouting`은 "동시 실행"만 막을 뿐,
   다음 위치 업데이트에서 또 이탈이면 그대로 재요청한다. (쓰로틀 없음)
2. **`/instructions` 폭주** — `ActionUploader`에는 "같은 action이면 스킵"하는 dedup이 있는데,
   `handleReroute` 성공 시 `actionUploader.reset()`이 `lastAction`을 매번 null로 만들어
   dedup을 무력화한다. 그 결과 동일한 `reroute` instruction이 매 사이클 전송된다.

## 상세 설계

### A. 재탐색 쿨다운 + 이동거리 게이트 (TMAP 폭주 차단)

직전 재탐색 이후 **20m 이상 이동**했거나 **10초 이상 경과**했을 때만 재요청한다.
제자리에 서 있으면 사실상 재요청이 멈춘다.

```kotlin
@Volatile private var lastRerouteAt = 0L
@Volatile private var lastRerouteLat = 0.0
@Volatile private var lastRerouteLng = 0.0

private suspend fun handleReroute(lat: Double, lng: Double) {
    if (isRerouting) return
    val now        = System.currentTimeMillis()
    val movedFar   = actionCalculator.haversine(lat, lng, lastRerouteLat, lastRerouteLng) > 20.0
    val cooledDown = now - lastRerouteAt > 10_000L
    if (!movedFar && !cooledDown) return          // 제자리 & 10초 이내 → 스킵

    isRerouting = true
    fetchRouteUseCase(lat, lng, config.destinationLat, config.destinationLng)
        .onSuccess { newSteps ->
            config.steps   = newSteps
            lastRerouteAt  = now
            lastRerouteLat = lat
            lastRerouteLng = lng
        }
    isRerouting = false
}
```

첫 재탐색은 `lastRerouteAt == 0`이라 `cooledDown`이 true가 되어 정상 허용된다.

### B. 업로더 dedup 복원 (/instructions 폭주 차단)

`handleReroute` 성공 콜백에서 `actionUploader.reset()` 호출을 제거한다.
그러면 `ActionUploader`의 action 기반 dedup이 살아나 동일 `reroute`는 처음 1회 +
30초 keep-alive만 전송된다. (경로 복귀 후 STRAIGHT/좌회전 등은 action이 달라 정상 전송)

## 테스트 방법
1. 정지 상태에서 이탈이 지속될 때, OkHttp 로그의 TMAP 요청이 매 2초 → 최대 10초 1회로 줄고
