# 경로 이탈 판정 개선 — 선분 수직거리 + 임계 완화 + 출발 유예

작성일: 2026.08.27

## 배경 / 문제

`ActionCalculator.calculate`의 경로 이탈 판정이 부정확해, 정상 경로 위에 있거나
GPS가 조금만 튀어도 `REROUTE`로 오판한다.

```kotlin
val minDistToRoute = steps.minOf { haversine(lat, lng, it.latitude, it.longitude) }
if (minDistToRoute > 30.0) return NavigationAction.REROUTE to 0.0
```

문제점:
1. **꼭짓점 거리**만 잰다. 사용자가 두 경로점을 잇는 선분 위에 있어도, 양쪽 꼭짓점이
   멀면 거리가 크게 나와 이탈로 오판한다. (원래는 "경로 선분까지의 수직거리"를 재야 한다)
2. **임계 30m가 너무 빡빡**하다. GPS 오차 + TMAP 출발점 스냅(50~100m)을 고려하면
   정상 이동 중에도 튄다.
3. **출발 스냅**: TMAP은 요청 출발 좌표를 가장 가까운 보행 도로로 스냅해 SP를 잡는다.
   사용자 GPS와 SP가 수십~백 m 벌어질 수 있어, 안내 시작 직후 즉시 이탈로 오판한다.

## 전제 (의존)

선분 수직거리는 **연속된 경로점이 실제 도로를 따라 촘촘해야** 정확하다.
`Point`(회전 지점)만 있으면 두 회전점을 잇는 직선이 굽은 도로를 벗어난다.
따라서 본 수정은 **PR #13 (TMAP LineString 경로점 반영, `fix/route-linestring-parsing`)이
병합된 뒤** 효과를 낸다. 코드상 독립이지만 정확도는 #13에 의존한다.

## 상세 설계

### 1. 선분 수직거리

각 연속 두 점 `(A,B)`이 이루는 선분까지의 최단(수직) 거리를 구하고 그 최소를 쓴다.
도보 스케일(선분 수십~수백 m)에서는 국소 평면 근사로 충분히 정확하다.

```kotlin
private const val OFF_ROUTE_THRESHOLD = 50.0   // m

/** 경로(연속 선분)까지의 최단 수직거리(m) */
private fun distanceToRoute(lat: Double, lng: Double, steps: List<RouteStep>): Double {
    if (steps.size == 1) return haversine(lat, lng, steps[0].latitude, steps[0].longitude)
    var min = Double.MAX_VALUE
    for (i in 0 until steps.size - 1) {
        val d = pointToSegment(lat, lng, steps[i], steps[i + 1])
        if (d < min) min = d
    }
    return min
}

/** 점 P에서 선분 A-B까지 최단거리(m). 국소 평면 근사. */
private fun pointToSegment(pLat: Double, pLng: Double, a: RouteStep, b: RouteStep): Double {
    val mPerLat = 110_540.0
    val mPerLng = 111_320.0 * cos(Math.toRadians(pLat))
    val px = pLng * mPerLng; val py = pLat * mPerLat
    val ax = a.longitude * mPerLng; val ay = a.latitude * mPerLat
    val bx = b.longitude * mPerLng; val by = b.latitude * mPerLat
    val dx = bx - ax; val dy = by - ay
    val len2 = dx * dx + dy * dy
    val t = if (len2 == 0.0) 0.0 else (((px - ax) * dx + (py - ay) * dy) / len2).coerceIn(0.0, 1.0)
    val cx = ax + t * dx; val cy = ay + t * dy
    return hypot(px - cx, py - cy)
}
```

### 2. 임계 완화

`30.0` → `OFF_ROUTE_THRESHOLD = 50.0`. GPS 오차 + 출발 스냅을 흡수.

### 3. 출발 유예 (hasEnteredRoute)

안내 시작 직후 사용자가 아직 경로에 진입하기 전(출발 스냅으로 수십 m 밖)일 때는
재탐색하지 않고 **직진 안내**만 한다. 한 번이라도 경로에 진입(≤임계)하면
그 이후부터는 정상적으로 이탈 시 재탐색한다.

```kotlin
val distToRoute = distanceToRoute(lat, lng, steps)
if (distToRoute <= OFF_ROUTE_THRESHOLD) {
    hasEnteredRoute = true
} else {
    return if (hasEnteredRoute) NavigationAction.REROUTE to 0.0
    else NavigationAction.STRAIGHT to distToDest      // 진입 전: 재탐색 보류
}
```

상태는 `ActionCalculator`가 `@Volatile private var hasEnteredRoute`로 보유하고,
`reset()`으로 초기화한다. `NavigationService.onStartCommand`에서 세션 시작 시 `reset()`을 호출한다.

### calculate 흐름 (교체 후)

```kotlin
fun calculate(...): Pair<NavigationAction, Double> {
    val distToDest = haversine(lat, lng, destLat, destLng)
    if (distToDest <= destRadius) return NavigationAction.ARRIVED to 0.0
    if (steps.isEmpty()) return NavigationAction.STRAIGHT to distToDest

    val distToRoute = distanceToRoute(lat, lng, steps)
    if (distToRoute <= OFF_ROUTE_THRESHOLD) {
        hasEnteredRoute = true
    } else {
        return if (hasEnteredRoute) NavigationAction.REROUTE to 0.0
        else NavigationAction.STRAIGHT to distToDest
    }

    // 이하 "다음 회전" 계산은 기존 로직 유지 (currentIdx, nextTurn, distToTurn)
    ...
}
```

`currentIdx`/`nextTurn` 등 다음 회전 탐색 로직은 그대로 둔다(꼭짓점 기준으로 충분).

## 테스트 방법
1. 실제 경로 위(30~40m 이내)에서 안내 시작 → REROUTE 대신 직진/좌회전/우회전이 뜨는지.
2. 경로를 50m 이상 벗어났다가 복귀 → 벗어났을 때만 REROUTE, 복귀 후 정상 안내.
3. 실내(대마고)처럼 출발 스냅이 큰 곳에서 시작 → 즉시 REROUTE 폭주 대신
   "직진" 안내로 대기하다가, 경로에 진입하면 정상 동작.
4. OkHttp 로그에서 정지/정상 이동 시 `reroute` instructions가 도배되지 않는지.
